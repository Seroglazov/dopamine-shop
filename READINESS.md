## Что добавлено локально

- server/checkout.mjs: проверка корзины на сервере, объединение одинаковых строк, проверка остатков, расчёт в целых копейках. Цена из браузера игнорируется. Концепты запрещены к продаже даже при ошибочном включении.
- server/yookassa.mjs: создание платежа с ключом идемпотентности, получение платежа и проверка суммы/заказа/статуса. Нет реальных запросов на списание денег; тесты используют подменённый транспорт.
- app.cjs и server/http.mjs: точка входа Passenger, раздача dist, GET /api/health и POST /api/checkout/quote. Приём заказов и платежей намеренно не выставлен до появления постоянного хранилища и резервирования остатков.
- .env.example: параметры домена, доставки и сервера. Реальные .env исключены из Git. Секреты не должны попадать в public или dist.

## Следующие этапы бэкенда

1. Постоянная БД MySQL: товары, варианты, остатки, заказы, строки заказа, платежи и журнал событий. Транзакционные резервы, уникальные ключи идемпотентности и освобождение неоплаченных резервов.
2. Оформление гостевого заказа: серверная валидация контактов и согласия, неизменяемый снимок цены/доставки, защищённый доступ покупателя к своему заказу.
3. ЮKassa: создание платежа после сохранения заказа и резерва. Webhook проверяет платёж повторным запросом к API; переход на return_url сам по себе не означает оплату. Повторные и запоздавшие события обрабатываются без повторных списаний остатков. Согласовать состав чека, налоги и отправку чеков с настройками магазина.
4. Администратор: защищённый вход, управление ценами/остатками, заказы, статусы, уведомления. Далее кабинет покупателя и доставка.
5. Проверить тестовые оплату/отказ/возврат, параллельные покупки последнего товара, повторный запрос, сбой сети, резервное копирование и восстановление БД.
6. Устранить замечания npm audit: 9 зависимостей с предупреждениями (6 high, 3 moderate), в том числе цепочка Tailwind/PostCSS. Не выполнять автоматическое обновление с --force: оно предлагает переход на Tailwind 4 и требует отдельной проверки стилей. Предупреждение сборки о нескольких package-lock.json на ПК относится к определению корня проекта; чужие lock-файлы не удалялись.

## Размещение

Работа ведётся локально под будущий Спринтхост; существующая публикация Sites не обновлялась. Спринтхост поддерживает Node.js 22 через Passenger: https://help.sprinthost.ru/howto/nodejs. Нужен именно актуальный Node.js, а не интерпретатор по умолчанию. app.cjs должен запускаться из закрытого корня приложения, публичная директория должна содержать только сборку dist. Нельзя загружать весь проект вместе с .env и .git в публичный public_html. Конкретные пути Passenger и MySQL настраиваются по аккаунту.

Локально: npm ci, npm test, npm run typecheck, npm run build, npm start. Переменные из .env.example задаются в окружении сервера; приложение не загружает .env автоматически. Без реального платёжного аккаунта и БД приём оплаты недоступен.

Справка ЮKassa: https://yookassa.ru/developers/payment-acceptance/getting-started/quick-start и https://yookassa.ru/developers/using-api/webhooks.
